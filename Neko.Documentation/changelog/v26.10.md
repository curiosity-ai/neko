# :icon-sparkles: Features

::: change {badge="New" title="Document mode — paged documents with a native Word download"}
A page whose front matter says `document: true` now builds as a **paged
document**: A4 (or Letter) sheets on a desk, with a **docx** button that
downloads the same pages as a real Word file. Like a deck, the whole document is
**one Markdown file**; a `---` rule starts a new page and can carry options
(`--- {layout="opener" art="squares" number="01"}`), and a file with no rule is
one flowing document that Word breaks into pages.

The download is built in the browser from the [docx](https://github.com/dolanmiu/docx)
library, which Neko ships in its own `assets/` folder — nothing comes from a CDN,
and nothing is downloaded until the button is clicked. It is **native Word
content, not a picture of the page**: one section per sheet, the running head and
foot as the header and footer with a live page-number field, paragraphs, lists and
tables you can edit, the ground and generated art floating behind the text, and
diagrams as pictures.

The theme's fonts are **embedded in the file** as obfuscated TrueType, under the
names the fonts carry, and `settings.xml` asks Word to keep them when a reader
saves — so the file looks the same on a machine that has never installed them.
:::

::: change {badge="New" title="Two document themes: neko and the Curiosity whitepaper"}
`theme: neko` is the default: a plain, readable page in Inter for headings,
lists, tables, code and callouts. `theme: curiosity` is the Curiosity brand's
whitepaper system — paper, ink, stone and deep blue with one signal square,
Schibsted Grotesk and Geist Mono — with sixteen layouts (cover, contents, section
openers, figures, key points, tables, listings, a customer quote, numbers, steps,
takeaways, a glossary and a back cover) and generated art (a dash field, squares,
bars and the pixel window). `--theme curiosity` re-themes every document that has
that theme.

New containers, scoped to documents: `cols`, `col`, `box`, `note`, `keypoint`,
`claim`, `lead`, `figure`, `flow` (boxes and arrows from a bullet list), `facts`,
`entries`, `steps`, `stats`, `quote`, `glossary`, `aside` and `art`, plus the
inline `[!mark]` table squares. The sample whitepaper — all 21 pages of
*Modern enterprise search* — is one Markdown file in the documentation.
:::

# :icon-wrench-simple: Improvements

::: change {badge="Improved" title="Decks and documents are single, self-contained HTML files"}
A presentation deck or paged document no longer loads anything: its stylesheet
and Tailwind utilities, the theme's fonts, icons, emoji, KaTeX, Mermaid,
highlight.js, the runtime and the PowerPoint/Word exporter are embedded in the
page, and local images (logo, favicon, figures) are inlined as data URIs. No CDN,
no Google Fonts and no request to the site's `assets/` folder, so a deck can be
saved, mailed or opened offline and still present and export the same.

Only what the page uses comes along — icons and emoji are cut down to the ones it
shows, and KaTeX and Mermaid only when it has math or a diagram. The third-party
files are vendored under `Neko/Resources/standalone/` (rebuilt with
`reference/standalone/build-standalone.py`); the `midnight` and `daylight` fonts
that used to come from Google Fonts now ship with Neko.
:::

::: change {badge="Improved" title="Updated dependencies"}
Neko now builds on Markdig 1.4.0, Transpose.Compiler.Library 26.10 and
LlmTornado 3.8.71. The test suite moves to NUnit 5, Playwright 1.63 and
SkiaSharp 4.153. MSBuild stays on 18.9, the last release that supports .NET 10.
:::

# :icon-bug: Fixes

::: change {badge="Fixed" title="Straight-edged SVG art exports as vector shapes, not pictures"}
The curiosity theme's generated art (bars, stair, field, glyphs) went into the
`.pptx` as pictures, and PowerPoint versions and viewers that draw the PNG
fallback showed it soft on a big screen. An SVG drawn only with straight edges in
flat colours now becomes native freeform shapes, one per fill or stroke, clipped
to the SVG's frame: a bar slide of 3,280 ticks is three shapes. Text, curves,
transforms, markers, dashes and gradients keep the picture. The deck that
prompted it went from 610 KB to 330 KB.
:::

::: change {badge="Fixed" title="Flow arrows export as PowerPoint lines with arrowheads"}
The curiosity theme draws the arrowhead between `flow` steps as a bordered box
turned 45 degrees. The pptx export cannot carry a CSS rotation, so PowerPoint
showed an unrotated corner, a hook rather than an arrow. Two custom properties
now ask the exporter for a native element: `--pptx-line: arrow` turns a thin bar
into a PowerPoint line with an arrowhead, and `--pptx: none` leaves a
screen-only decoration out. The theme's connectors use both, so each arrow is
one editable line.
:::

::: change {badge="Fixed" title="Exports keep their styles inside a wrapping host"}
The pptx and docx exporters restage the page in an off-screen frame from the
page's stylesheets, and read them from `<head>` only. A host that wraps the page
in its own skeleton (a sandboxed preview) moves that `<head>` into `<body>`,
and the file came out unstyled while the page looked right. The exporters now
take every stylesheet in the document.
:::

::: change {badge="Fixed" title="Large stat values no longer wrap in PowerPoint"}
PowerPoint sets the embedded Schibsted Grotesk a hair wider than the browser,
and a box sized to a number such as `€1,715` wrapped its last digit onto a
second line. Stat values in the curiosity theme are `nowrap`, which the export
writes as an unwrapped text box.
:::

::: change {badge="Fixed" title="[!embed](url) renders the embed again"}
The renderer read only a `src` attribute, while the documented form puts the URL
in parentheses, so every `[!embed](url)` rendered an empty paragraph. The URL in
parentheses is now used (with `src=` and `url=` still accepted), and the
documented attributes work: `aspect` (16:9 by default), `width`, `height`,
`allowFullScreen`, `el` (`iframe`, `video`, `embed`, `object`) and `text`, which
becomes a caption. Relative URLs to a file in the site, such as
`/assets/report.html`, embed too. The editor snippet now inserts the documented
form.
:::

::: change {badge="Fixed" title="Search index ids are URL paths on every OS"}
A site built on Windows wrote its page ids into `search.json` with the OS
separator (`blog\post.html`). The inline blog search only accepts results
under `blog/`, so on such a build the search box answered every query with
"No results found", and a `--focus` session could not carry pages over from
the previous index either. Ids and section parents are now written with
forward slashes whatever the build machine, and the blog search also reads an
index an older build left behind.
:::

::: change {badge="Fixed" title="No scroll or icon pop-in after a page load"}
A link to a heading (`page#section`, as every search result is) left the reader
at the top of the page until `load`, then glided down to the heading. The jump
now happens as soon as the page is parsed, and the realignment after `load` is
instant. The table of contents scrolls only its own pane, instead of every
scrollable ancestor, and its highlight bar no longer slides in from the top on
load. The Regular Rounded icon font is preloaded, so icons are there in the
first paint instead of popping in a frame later and moving the sidebar.
:::
