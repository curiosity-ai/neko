# :icon-wrench-simple: Improvements

::: change {badge="Updated" title="Updated dependencies"}
`Voxwerk` and `Voxwerk.Voices.English` move to 26.10.6691. The English voice
catalog shipped in 26.10.6674 was empty, so `neko voices` listed nothing and a
`narration: voice:` naming a catalog voice (for example
`en-us-franklin-delacroix`) could not be resolved; 26.10.6691 carries the voices.
The test project's MSBuild packages stay on 18.9.6: 18.10.1 no longer supports
net10.0.
:::

# :icon-bug: Fixes

::: change {badge="Fixed" title="A catalog voice stays one speaker across the voice-over"}
`narration: voice: <catalog id>` used to hand only the voice's description to the
VoiceDesign model, which designs a new voice for every sentence, so the narrator
drifted from line to line. A catalog voice is now cloned from its reference
recording with the Base checkpoint (`Qwen/Qwen3-TTS-12Hz-1.7B-Base`), so every
sentence is the same speaker. The reference samples of the English catalog ship
with Neko (`Voxwerk.Voices.English.*` sample packages). `clone: false` brings back
the designed voice; `cloneModel:` picks another Base checkpoint. Takes made the old
way are keyed differently and are re-synthesized once.
:::

::: change {badge="Fixed" title="Screenshots in a browser, window or phone frame stand still and are not cropped"}
An image-only paragraph inside a frame took the default `zoom` entrance, so the
screenshot grew inside chrome that had already settled. It now arrives with its
frame. A `browser` or `window` holding one screenshot takes the screenshot's
proportions instead of stretching to the scene and cropping it with
`object-fit: cover`, and a screenshot written straight into the frame no longer
picks up the 40 px margin meant for Markdown screens. In the curiosity theme the
frame takes the scene's ground (`--card`), so a dark screenshot on an `ink` scene
sits in dark chrome.
:::

::: change {badge="Fixed" title="A figure's picture fits the slide in the curiosity deck"}
A `::: figure` image is sized to the slide's width, so a screenshot under a
heading ran off the fixed canvas and took its caption with it. Once the images of a
slide have loaded, a figure that overflows has its picture capped by the overflow,
keeping its proportions, on screen and in the PowerPoint export.
:::
