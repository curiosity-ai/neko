# :icon-wrench-simple: Improvements

::: change {badge="Improved" title="The test suite no longer needs a commercial image licence"}
`Neko.Tests` decoded screenshots with SixLabors.ImageSharp for the Tailwind
visual-parity test. ImageSharp 4.0 moved to the Six Labors Split License and
enforces a paid key **at build time**, so once the package drifted past 4.0 the
whole test project stopped building, whether or not anyone ran that test.

Screenshots are now decoded with SkiaSharp, which is MIT and already the imaging
library used elsewhere in the Curiosity stack. The comparison is unchanged: same
size check, same per-channel tolerance.
:::

::: change {badge="Improved" title="Live Tesserae samples compile against current Tesserae releases"}
The Transpose compiler Neko embeds to build `tesserae` code blocks was a release
behind the Tesserae packages shipping today. A site pinning a current Tesserae
refused to compile every one of its samples with `TPS0008: This project
references assemblies built by a newer Transpose`, and because the failure is
per sample rather than per build, it surfaced as a page full of placeholder
previews and a `gen-tesserae-heights` run that measured the error box instead of
the sample.

Updating the global `Transpose.Compiler` tool did not help, since Neko uses its
own embedded copy. The embedded compiler is now current, so samples compile and
their heights measure again.
:::

# :icon-bug: Fixes

::: change {badge="Fixed" title="Long content overflowed alerts and notes"}
A note (`!!! warning …`, or a GitHub-style `> [!WARNING]`) laid its icon and its
body out as a flex row, and the body column kept the minimum width its content
asked for. A wide code block, a long Windows path or an unbreakable token
therefore stretched the note past the content column, so the text ran under the
"On this page" rail and off the right edge of the page.

The body column can now shrink below that width: prose and inline code wrap
inside the note, and what cannot wrap scrolls in place — a code block keeps its
horizontal scrollbar, and a table inside a note is its own scroll container
instead of pushing the note open.
:::

::: change {badge="Fixed" title="Back and forward didn't scroll to the anchor"}
On a page with anchors, stepping through history with the browser's back and
forward buttons changed the URL fragment but left the reader where they were:
going back from `#configuration` to `#installation` still showed the
*Configuration* heading.

The cause is that the content pane (`#main-scroll`) is the scroller, not the
document. A browser restores the document's offset on a history step, and for a
same-page fragment step there is no document offset that corresponds to the
fragment at all — so nothing moved. Neko now re-aligns the pane with the current
fragment on every same-document fragment change, so back and forward land on the
heading the URL names. The scroll matches an ordinary anchor click (same target,
same smooth behaviour), and stepping back past the *first* anchor returns to the
position the reader had scrolled to themselves rather than jumping to the top.

Cross-document back/forward is untouched: there the browser restores the pane
from its own cache.
:::
